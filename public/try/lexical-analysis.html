What goes in, what comes out

Lexical analysis is worth teaching as a contract rather than as a description. The stage promises very little, and most of the marks come from knowing exactly how little that is.

Stages of compilation (lexical analysis, syntax analysis, code generation and optimisation).OCR H446 specification, 1.2.2 (e). The specification names the stage and stops. Everything else on this page is commentary.

In

  • One stream of characters, read once, left to right
  • No structure, no line meaning, no idea which language construct is being read
  • A position counter, so every character knows its line and column

Out

  • A stream of tokens, each carrying a type, a value and the position it came from
  • A symbol table holding every identifier met, with space for the type and the address that later stages fill in
  • A list of any characters that belong to no token at all

Explicitly not

  • No check that the tokens are in a sensible order, which is stage two
  • No arithmetic. The lexer reads 4 and 2 and never notices the multiplication sign between them
  • No whitespace, indentation or comments. They did their job and are discarded
  • No data types and no addresses yet, only the names

Where the editor stops and the translator starts

      Why the positions travel with the tokens
      
Every token carries the line and column of the character it started at. The parser, two stages later, has no access to the source text at all, so when it rejects a token sequence the only way it can tell anybody where the problem is, is by reading the position the lexer attached. An error message pointing at the right line is a service provided by stage one.

    

  






  

    

      
When the lexer finds something it cannot read

      
There are only two ways to fail at this stage: a character that belongs to no token, and a token that opens and never closes. Everything else a pupil calls a syntax error is caught later.
